# Mouse Lab — состояние проекта

## Описание

Mouse Lab — десктопная игра на C++17 и raylib.

Игрок управляет лабораторной мышью, которая проходит лабиринт. Проект постепенно развивается в игру с экрановыми переходами, лабораторией, профилем игрока, режимами забега и будущими ML-механиками.

## Сборка

Проект собирается через CMake + Ninja.

Основной исполняемый файл:

```text
build/mouse_front.exe
```

Основная команда сборки:

```powershell
cmake --build build
```

## Базовое разрешение

Текущее базовое разрешение игры:

```text
960x540
```

Пока проект не использует полноценную систему virtual resolution или fullscreen scaling.

## Текущий поток экранов

Актуальный игровой путь:

```text
MainMenu -> ProfileSetup -> Intro -> LaboratoryHub -> MazeRun
```

## Реализованные экраны

### MainMenuScreen

Главное меню игры.

Сейчас используется для входа в игровой поток.

### ProfileSetupScreen

Экран создания профиля игрока.

Сейчас содержит:

- ввод имени;
- выбор аватара;
- переход дальше по игровому потоку.

### IntroScreen

Экран вступления.

Сейчас используется как переход между созданием профиля и лабораторией.

### LaboratoryHubScreen

Экран лаборатории.

Сейчас содержит:

- приветствие игрока;
- блок experiment console;
- запуск ручного забега в лабиринте.

### MazeRunScreen

Экран забега в лабиринте.

Текущая цель этого экрана:

- быть полноценным экраном забега;
- рисовать фон, header, panel, footer;
- размещать лабиринт внутри отдельной панели;
- рисовать modal `LEVEL COMPLETED` и затемнение поверх лабиринта (относительно `origin`);
- рисовать и обрабатывать кнопку `RESET`, сбрасывая уровень через `Game`;
- давать возможность вернуться в `LaboratoryHub`.

## Gameplay

Основная игровая логика находится в:

- `Game`
- `Maze`
- `Mouse`

Сейчас реализовано:

- лабиринт задан строками;
- мышь двигается по клеткам;
- движение выполняется стрелками;
- один шаг происходит на одно нажатие клавиши;
- стены блокируют движение;
- считается количество успешных ходов `MOVES`;
- при достижении цели уровень считается завершённым;
- `Game` хранит состояние завершения и счётчик ходов и предоставляет `IsLevelCompleted()`, `GetMoveCount()` и `ResetLevel()`;
- modal `LEVEL COMPLETED`, затемнение и кнопка `RESET` рисуются и обрабатываются на стороне `MazeRunScreen`.

## Архитектура экранов

`GameApp` хранит конкретные объекты экранов и переключает их через `ScreenType`.

Сейчас проект не использует:

- `std::unique_ptr<Screen>`;
- фабрики экранов;
- screen registry;
- отдельный screen manager.

Это осознанное решение на текущем этапе, чтобы проект оставался понятным и простым.

## AppContext

`AppContext` хранит общий контекст приложения.

Сейчас в нём находятся:

- размер экрана;
- профиль игрока.

`AppContext` передаётся по ссылке в экраны, которым нужны общие данные.

## Текущие технические ограничения

- базовое разрешение зафиксировано как `960x540`;
- нет полноценной адаптивности под разные размеры окна;
- нет virtual resolution;
- нет fullscreen scaling;
- нет системы уровней;
- нет сохранений;
- нет загрузки ассетов;
- нет полноценной поддержки русского текста через отдельный шрифт;
- лабиринт пока задан прямо в коде;
- графика пока рисуется raylib primitives.

## В работе

Текущий технический фокус:

- довести `MazeRunScreen` до полноценного экрана забега;
- сохранить старую механику движения;
- не ломать существующие переходы между экранами.
